# 04 · 部署与运维

本文覆盖**上线前的实际动作**：Master 部署、发布产物入库、Agent 一键部署、  
Agent 自升级与回滚、以及一份可以逐条打勾的验证清单。

- 面向读者：负责上线与日常运维的人（需要 root / 管理员权限）。
- 与其它文档的关系：`01-执行摘要` 说明做了什么，`02-落地实施计划` 是验收标准，  
  `03-工具链安装与环境搭建` 是**开发机**上的 Go / minisign / Chrome 安装。  
  本文是唯一一份"把这套东西装到真机器上"的操作手册。
- 所有命令都给出**预期输出**：部署类操作的失败常常是静默的（服务起来了但没监听、  
  装上了但没上报），只看"命令退出码为 0"会漏掉一大半问题。

## 0. 上线前核对（5 分钟）

| 项         | 要求                                                            | 检查方式                                      |
| --------- | ------------------------------------------------------------- | ----------------------------------------- |
| Master 机器 | 1 核 1G 起步；Linux（systemd）或 Windows Server                      | `systemctl --version` / `$PSVersionTable` |
| 磁盘        | 按保留期估算：30 天约 1~2 GB（含 10s 高精度层）                               | `df -h /var/lib`                          |
| 域名与 DNS   | 公开站与（可选）管理端各一个域名，已解析到本机                                       | `dig +short status.example.com`           |
| 端口        | 公开站 8080（或 80/443）、管理端 8081                                   | `ss -lntp`                                |
| TLS 决策    | 四选一：`acme`（自动）/ `files`（已有证书）/ `selfsigned`（自签）/ `none`（前置反代） | 见 §2.4                                    |
| 注册码来源     | 后台节点页生成，**一次性、短时有效**，装完即失效                                    | 见 §3                                      |
| 备份位置      | 与本机**不同的**存储；`master.key` 必须另外离线保存                            | 见 §5                                      |
| 时间同步      | 时间不对会导致注册码、令牌、告警时间全部错位                                        | `timedatectl`                             |



> ⚠️ **`master.key` 是本系统唯一不可再生的东西**：告警渠道凭证（TG Bot Token、  
> SMTP 口令）都用它加密。它丢了，渠道凭证就解不开，只能重新填一遍；  
> 它泄漏了，等于渠道凭证泄漏。**离线另存一份，不要放进备份目录。**

## 1. 从源码构建发布产物

发布产物 = Master 二进制 + 各平台 Agent 二进制 + `SHA256SUMS`（+ minisign 签名）。

```bash
# Linux/macOS 开发机
make dist VERSION=1.0.0        # → dist/1.0.0/，并生成 SHA256SUMS
make master                    # → bin/probe-master（部署到 Master 机器）

# Windows（无 make）
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Version 1.0.0 -Dist
```

产物命名固定为 `probe-agent_<os>_<标签>[.exe]`，标签取值：

| 标签                                                      | 说明                                    |
| ------------------------------------------------------- | ------------------------------------- |
| `linux_amd64` `linux_arm64` `linux_386` `linux_riscv64` | 常见 Linux                              |
| `linux_armv7` `linux_armv6`                             | 32 位 ARM（**产物名是 armv7/armv6，不是 arm**） |
| `freebsd_amd64` `freebsd_arm64`                         | FreeBSD                               |
| `windows_amd64` `windows_arm64`                         | Windows                               |

**发布标签会被写进二进制**（`-ldflags "-X .../internal/dist.PlatformTag=<os>_<标签>"`），  
`probe-agent upgrade` 靠它挑对产物名。用 `probe-agent version` 可以看到自己身上的是哪个：

```
probe-agent 1.0.0 linux/arm (发布标签 linux_armv7)      ← 发布构建，正确
probe-agent 1.0.0 linux/arm (发布标签 linux_arm)        ← 随手 go build 的，升级会报"该平台未发布此版本"
```

签名（可选但推荐，见 `docs/05-实现细节与常见问题.md` 的「发布产物签名」）：

```bash
minisign -Sm dist/1.0.0/SHA256SUMS      # 用离线私钥签，产出 SHA256SUMS.minisig
```

## 2. Master 部署

### 2.1 Linux（systemd）一键

```bash
sudo cp bin/probe-master /tmp/probe-master
sudo sh scripts/deploy-master.sh \
  --bin /tmp/probe-master \
  --public-origin https://status.example.com \
  --admin-origin  https://admin.example.com \
  --admin-user ops
# 回车后交互式输入管理员口令（不回显、不进 shell 历史）
```

也可以先 `export PROBE_ADMIN_PASSWORD='...'` 或传 `--admin-password`（不推荐，会进历史）。

脚本做七件事：**建 `probe` 低权限用户与目录（数据目录 0700）→ 安装二进制 →  
写 `master.yaml` → `init-admin` → 写 systemd 单元（含沙箱加固）→ 启动 → 健康检查 →  
打印后续待办**。

常用参数：

| 参数                | 默认                      | 说明                                                                          |
| ----------------- | ----------------------- | --------------------------------------------------------------------------- |
| `--dir`           | `/etc/probe-master`     | 配置目录（含 `master.key`）                                                        |
| `--data`          | `/var/lib/probe-master` | 数据目录（库、`dist/`、`themes/`）                                                   |
| `--public-listen` | `0.0.0.0:8080`          | 公开站监听                                                                       |
| `--admin-listen`  | `127.0.0.1:8081`        | 管理端监听（配反代时保持只本机）                                                            |
| `--dist-base`     | 空                       | 发布文件镜像前缀。**注意**：它是数据库设置，脚本无法写入 `master.yaml`，只会提示你去管理端「设置 → 安装与下载」填「二进制下载源」 |
| `--no-service`    | —                       | 只装不注册服务（容器 / 非 systemd）                                                     |
| `--force-config`  | —                       | 覆盖已有 `master.yaml`                                                          |

**幂等**：重复执行不会重建数据目录，也不会覆盖已有 `master.yaml`（除非 `--force-config`），  
走的是"停服务 → 换二进制 → 启动"的升级路径。

> **为什么脚本要专门修一遍文件归属**：服务以 `User=probe` 运行，而脚本的每一步  
> （建目录、写配置、`init-admin` 建库与主密钥）都是以 root 执行的。  
> 目录的 `chown` 在**文件被创建之前**做，覆盖不到后来的新文件——所以 `init-admin`  
> **之后**还要再统一 `chown` 一次。漏掉这一步的表现是"服务一起来就退出"或  
> `attempt to write a readonly database`，而脚本自己的日志一切正常。  
> 脚本会把最终权限 `ls -l` 出来，方便你核查（以 root 跑 `test -r` 永远是 true，  
> 那种"检查"只会给出虚假的安心）。

预期输出（末尾）：

```
==> 5/7 写 systemd 单元
    已启用并启动
==> 6/7 健康检查
● probe-master.service - Server Probe Master
     Active: active (running)
==> 7/7 完成。接下来要做的事
```

### 2.2 Windows（计划任务）一键

以**管理员** PowerShell 执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-master.ps1 `
  -Bin .\bin\probe-master.exe -AdminUser ops
# 会提示输入口令（SecureString，不回显）
```

参数与 Linux 版一致（`-Dir` `-Data` `-PublicListen` `-AdminListen` `-PublicOrigin`  
`-AdminOrigin` `-DistBase` `-NoStartupTask` `-ForceConfig`）。

数据目录会用 ACL 收成"仅 Administrators 与 SYSTEM"，等价于 Linux 的 0700。

> Master 在 Windows 上没有内置服务封装（Agent 才有），这里用  
> "开机时以最高权限运行"的计划任务实现自启，并配了失败重启。  
> 需要真正的服务形态（可 `Restart-Service`）时用 NSSM / WinSW 包一层，  
> 命令行仍是一句 `probe-master.exe -config <配置文件>`。

### 2.3 容器 / 无 systemd 环境

```bash
sh scripts/deploy-master.sh --bin ./probe-master --no-service \
    --dir /data/probe-master --data /data/probe-master/data
# 然后自己托管：/usr/local/bin/probe-master -config /data/probe-master/master.yaml
```

Alpine(OpenRC) 上脚本会提示"没有 systemd"，改用 `rc-service` / `supervisord` 托管。  
容器里注意：**公开站要监听 `0.0.0.0`**，管理端建议留在容器内网或走反代。

### 2.4 首次登录后的必做项

> **先分清两套配置面（踩过一次的坑）**：`install.mode` / `install.master_url` /  
> `install.dist_base` 这些**不是 `master.yaml` 的字段**，而是**数据库设置**——代码用  
> `repo.GetSettingDefault("install.master_url", ...)` 读取。`MasterConfig` 结构里没有  
> `install` 这个键，而 `LoadMaster` 是**严格解析**（`KnownFields(true)`）的：把 `install:` 写进  
> `master.yaml` 会**直接启动失败并点名是哪个键**，**不是**"写了也不生效"。它们的唯一入口是管理端  
> **「设置 → 安装与下载」**。
>
> 其中 `install.master_url` 有个便利的回落：**未设置时取 `public_origin`**  
> （见 `cmd/probe-master/main.go` 的 `MasterURL` 闭包）。所以给 `master.yaml` 配了  
> `public_origin`（即部署时给了 `--public-origin`），就不必再单独设它。  
> 反过来，**千万别把它写成 `0.0.0.0` 或 `[::]`**——那是"本机所有网卡"的**监听**写法，  
> 不是可连接的目的地址；这种错要到装第一台 Agent 时才会暴露。

1. **启用 TOTP 并保存恢复码**（管理端 → 系统 → 安全）。恢复码是唯一的"手机丢了"退路，  
   打印或存进密码管理器，**不要只留在浏览器里**。
2. **配 TLS**。`master.yaml` 的 `tls.mode`：
   | 模式           | 适用                | 关键项                                       |
   | ------------ | ----------------- | ----------------------------------------- |
   | `none`       | 前面有反代终止 TLS（最常见）  | 必须配 `trusted_proxies`                     |
   | `acme`       | 本机直接对外、有公网 80/443 | `tls.acme.domain`、`tls.acme.email`        |
   | `files`      | 自己管证书             | `tls.cert_file` / `tls.key_file`（30s 热加载） |
   | `selfsigned` | 内网自用              | SAN 含 IP；Agent 侧配 `spki_sha256`           |
3. **配 `trusted_proxies`**（前置反代时）。它决定两件事：`X-Forwarded-For` 是否可信  
   （决定限速与审计里的真实 IP），以及是否下发 `__Host-` + `Secure` Cookie。  
   漏配的表现是"登录后立刻掉线"或"限速打到反代身上"。
4. **源分离（可选，推荐）**：填 `public_origin` / `admin_origin`，Host 不匹配时返回 421。
5. **外部心跳（可选）**：填 `heartbeat_url`，Master 停止时由外部服务告警——这是  
   "Master 整机挂掉"唯一还能通知你的路径（本机告警此时已经发不出去了）。
6. **站点形态**：决定公开看板与后台是"两个域名"还是"一个站点"，见 §2.5。

### 2.5 公开看板与后台：两个域名，还是一个站点

在管理端 **「系统设置 → 站点形态」** 里切换，**改完即时生效，不需要重启**。

| 形态                    | 适用场景                | 效果                                              |
| --------------------- | ------------------- | ----------------------------------------------- |
| 同站（`single`）          | 小站、自己用，不想配两个域名      | 一个域名同时提供公开看板与 `/admin/`，两边不区分域名                |
| 分离（`split`）           | 对外展示与自用分开（推荐）       | 公开域名只服务公开路径、管理域名只服务管理路径；**用错域名返回 421**          |
| 跟随配置文件（`auto`，默认）     | 升级前就已经配了 host 白名单   | 配了就分离、没配就同站——与升级前的行为**完全一致**                    |

配套两项是 **公开域名清单 / 管理域名清单**（一行一个，可带端口，如 `admin.example.com:8443`）。

**三个容易踩的点：**

1. **两个域名可以指向同一个端口。** 分离靠的是 Host，不是监听地址。`master.yaml` 里的  
   `admin_listen` 只在你确实想再开一个本地端口时才需要填；前置反代把两个域名都转发到  
   同一个端口是最常见的部署方式。
2. **选「分离」必须把两个清单都填上**，否则保存会被**直接拒绝**。这是防自锁：  
   分离 + 缺管理域名，会让管理后台在保存成功后的**下一个请求**上返回 421——  
   而把它改回来恰好需要访问后台，等于把自己锁在门外。
3. **后台这两项会顶替 `master.yaml` 里的同名清单**（不是追加）：填了就以后台为准，  
   留空则回落到配置文件。启动日志会打印**最终生效**的形态与清单；改设置时也会记一条日志，  
   因为这类改动的症状（"后台突然打不开""某个域名突然 421"）不伴随重启，很容易被误判成网络问题。

**反向代理样例**（Caddy；两个域名都转发到同一个端口，由 Master 按 Host 判断该服务谁）：

```caddyfile
status.example.com {
    reverse_proxy 127.0.0.1:8080
}
admin.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Nginx 同理，一个 `server` 块里写两个 `server_name` 指向同一个 `proxy_pass` 即可；  
别忘了把反代所在网段填进 `trusted_proxies`（否则 Master 看到的源 IP 是代理的）。

> **为什么域名不匹配返回 421 而不是 404**：这是**部署配置错误**的特征（域名解析指过来了、  
> 但这里不服务它），421 让运维一眼看出是"域名对不上"，比一个 404 好排查得多；  
> 而它本身不泄露任何内容——错误页与 JSON 都只说明"该域名不服务于这个接口"。  
> ACME 的 `/.well-known/` 挑战路径豁免这条判断（CA 是按 IP 访问的，永远命中不了域名白名单）。

> **明文 HTTP 直连 IP 的部署**：把访问用的 `IP:端口` 也写进对应清单，或干脆把形态设为「同站」。  
> 清单里只写域名而实际用 IP 访问，表现就是**所有请求 421**。

## 3. 发布产物入库（Agent 安装与升级的来源）

```bash
# 1) 把签名好的产物推到发布源（GitHub Releases / 对象存储 / 自家 CDN）
#    目录结构：<发布源>/1.0.0/{probe-agent_*, SHA256SUMS, SHA256SUMS.minisig}

# 2) 在 Master 上拉取入库（写进 data_dir/dist/1.0.0/）
sudo -u probe probe-master dist pull \
  --config /etc/probe-master/master.yaml \
  --version 1.0.0 \
  --from https://releases.example.com/1.0.0 \
  --pubkey /etc/probe-master/minisign.pub
```

预期输出：

```
已获取 SHA256SUMS（12 条），来源 https://releases.example.com/1.0.0/SHA256SUMS
  ✓ probe-agent_linux_amd64       7.8 MB  a1b2c3d4…
  ...
完成：12 个文件已校验并写入 /var/lib/probe-master/dist/1.0.0
```

要点：

- **`--pubkey` 不要省**。不加会打印一行"已跳过验签"的提示——此时若发布源被劫持，  
  攻击者可以把 `SHA256SUMS` 一起换掉，哈希校验会**全部通过**却装上投毒二进制。
- 任一文件校验失败会**整体回滚**，不留"半套可用"的错觉。
- 加 `--dry-run` 只校验不写盘；加 `--platform linux_amd64` 只拉一个平台。
- 重复拉同一个版本是安全的（覆盖写）。

### 3.1 两套 `/dist/` 路径语义（重要）

| 路径                | 含义                            | 谁在用                       |
| ----------------- | ----------------------------- | ------------------------- |
| `/dist/<版本>/<文件>` | **权威存放位置**，就是磁盘上的结构           | 自升级、后台"发布文件"页、`dist pull` |
| `/dist/<文件>`      | **最新版本的别名**（找不到同名文件时落到最新版本目录） | 安装脚本（它不知道版本号）             |

安装脚本取 `$DIST_BASE/probe-agent_linux_amd64` 与 `$MASTER_URL/dist/SHA256SUMS`；  
别名的"最新版本"与自升级用的是同一套规则，**因此新装节点与升级节点永远拿到同一个版本**。  
根目录下若手工放了同名文件，以显式文件为准。

自检：

```bash
curl -fsS https://status.example.com/dist/SHA256SUMS | head -1     # 应当有内容
curl -fsSI https://status.example.com/dist/probe-agent_linux_amd64 | head -3
```

> 未生成有效注册码时（`install.mode: on_demand` 的默认行为）这两个 URL 会返回 404——  
> 这是设计如此：不该长期匿名分发二进制。升级不受影响，它走节点令牌鉴权。

## 4. Agent 一键部署

### 4.1 注册码从哪来

管理端 → 节点 → **生成注册码**。注册码的特征：

- **一次性**：注册成功即失效（同一个码第二次用返回 401）。
- **短时有效**：过期需重新生成。
- **绑定节点**：注册后随即签发该节点的令牌。

### 4.2 Linux / FreeBSD 一键

```bash
curl -fsSL https://status.example.com/install.sh | sudo sh -s -- --code ABCD-EFGH-JKLM
```

不想让注册码出现在 shell 历史里，用环境变量传：

```bash
sudo PROBE_CODE=ABCD-EFGH-JKLM sh -c 'curl -fsSL https://status.example.com/install.sh | sh'
```

脚本做六件事：查 root → **按 `uname` 判定平台**（`armv7l`→`armv7`，与产物名一致）→  
下载二进制 → **minisign 验签（若内置公钥）→ SHA-256 校验** → 安装到  
`/usr/local/bin/probe-agent`（不可写时退到 `/opt/probe-agent`）→  
`probe-agent install` 注册服务（容器里自动加 `--no-service`）。

对"管道执行"有顾虑时改用分步方式：

```bash
curl -fsSLo /tmp/install.sh https://status.example.com/install.sh
less /tmp/install.sh                       # 先看
sudo sh /tmp/install.sh --code ABCD-EFGH-JKLM
```

### 4.3 Windows 一键

管理员 PowerShell 里执行**一行**：

```powershell
& ([scriptblock]::Create((irm https://status.example.com/install.ps1))) -Code 'ABCD-EFGH-JKLM'
```

不要写成 `irm ... | iex`：`iex` 无法给脚本传 `-Code` 参数，会停在校验注册码那一步。

### 4.4 装完确认

```bash
# Agent 侧
/usr/local/bin/probe-agent version                 # 版本 + 发布标签
systemctl status probe-agent                        # 或 rc-service / sc query
journalctl -u probe-agent -n 50                     # 或 /var/log/probe-agent.log
```

管理端"节点"页应出现该节点并转为**在线**（在线判定约 40 秒），公开看板同样可见。  
没出现时按 §6 排查。

## 5. Agent 自升级

### 5.1 查有没有新版本

```bash
probe-agent upgrade --check
# 可升级：1.0.0 -> 1.0.1（probe-agent_linux_amd64，7.8 MB）
# 或
# 已是最新：1.0.1（probe-agent_linux_amd64）
```

默认读 `/etc/probe-agent/agent.yaml`（FreeBSD 是 `/usr/local/etc/probe-agent/agent.yaml`）；  
自定义路径用 `--config`。

### 5.2 升级

```bash
sudo probe-agent upgrade
# 已升级 1.0.0 -> 1.0.1（8123456 字节）
# 备份：/usr/local/bin/probe-agent.old
# 请重启服务使新版本生效：systemctl restart probe-agent
```

| 参数                | 作用                          |
| ----------------- | --------------------------- |
| （无）               | 升到 Master 上的最新版本            |
| `--check`         | 只查询，不下载                     |
| `--dry-run`       | 下载并校验，**不替换**（用来验证网络与校验链路）  |
| `--version 1.0.1` | 指定版本（也可用于显式**降级**或重装）       |
| `--rollback`      | 把上一次备份换回来                   |
| `--target <路径>`   | 替换指定文件（默认是当前进程自身；用于离线/异机演练） |

行为要点：

- **先校验后落地**：下载到同目录的 `<目标>.new`，SHA-256 对上才改名，  
  中途失败不会在目标位置留下任何东西。
- **绝不主动降级**："比最新还新"也算无需动作（Master 回滚版本时不会把全网一起拖下去）。
- **不自行重启**：替换完成后进程里还是旧代码，必须重启服务才生效（命令脚本会打印出来）。

### 5.3 重启服务（使新版本生效）

```bash
sudo systemctl restart probe-agent      # systemd
sudo rc-service probe-agent restart     # Alpine/OpenRC
sudo service probe-agent restart        # SysV / OpenWrt(procd) / FreeBSD
Restart-Service probe-agent             # Windows
```

systemd 单元是 `Restart=always`，所以也可以 `sudo systemctl kill -s TERM probe-agent`  
让它在 5 秒后自动拉起来——但**不会**因为你替换了文件就自动重启，必须显式触发一次。

### 5.4 批量升级

```bash
for h in node1 node2 node3; do
  echo "== $h"
  ssh "$h" 'sudo probe-agent upgrade --check && sudo probe-agent upgrade && \
            sudo systemctl restart probe-agent && probe-agent version'
done
```


建议先在一台上跑 `--dry-run` 验证发布链路，再全量。**逐台滚动**，不要一次全换：
如果新版本有问题，`--rollback` 需要那台机器还在（`<目标>.old` 备份在本地）。

### 5.5 回滚

```bash
sudo probe-agent upgrade --rollback
# 已还原为上一版本。请重启服务使新版本生效：systemctl restart probe-agent
sudo systemctl restart probe-agent
```

回滚不会删掉"被换下来的那份"，而是挪成 `<目标>.broken` **留现场**：

| 文件 | 含义 |
| --- | --- |
| `/usr/local/bin/probe-agent` | 当前生效的 |
| `.../probe-agent.old` | 上一次升级前的（`--rollback` 的来源） |
| `.../probe-agent.broken` | 上一次回滚时换下来的（可删，或拿去复盘） |

## 6. 故障处理

升级与取件相关的错误，按信息对照处置：

| 现象 / 信息 | 含义 | 处置 |
| --- | --- | --- |
| **服务起不来 / 健康检查 20 秒内探不到公开 API** | 多半是**归属**问题：服务以 `probe` 用户运行，而 `master.yaml`、`master.key`、`probe.db` 是 root 属主（0640/0600/0644） | `ls -l /etc/probe-master/master.yaml /etc/probe-master/master.key /var/lib/probe-master/probe.db`；确认三者的属主/属组是 `probe`（`deploy-master.sh` 会在 `init-admin` **之后**统一修正归属——顺序很重要，早于建库就覆盖不到新文件）。`journalctl -u probe-master -n 50` 里通常是"读不到配置"或 `attempt to write a readonly database` |
| Agent 装上了但连不上 Master | `install.master_url` 指向了不可达的地址（最常见的是 `0.0.0.0`——那是"本机所有网卡"，不是目的地址），或方向不对（明文 HTTP 部署却回填了 `https://`） | 在管理端把 `install.master_url` 改成 Agent 真正能访问的地址；不写该键时 Master 按请求的 Host 回填 |
| `该平台未发布此版本：linux_armv7` | 发布产物里没这个平台 | 重新 `make dist` 并 `dist pull`；或确认 `probe-agent version` 里的发布标签是不是 `linux_arm`（随手 `go build` 的产物） |
| `Master 上还没有任何已发布版本（先执行 probe-master dist pull）` | `data_dir/dist/` 下没有合法版本目录 | 执行 `dist pull`；目录名必须是纯数字点分（`nightly-*` 会被忽略） |
| `该版本缺少 SHA256SUMS` | 版本目录存在但没有校验和 | 重新 `dist pull`（校验和是信任根，缺了必须拒绝） |
| `服务端未返回校验和（X-Checksum-Sha256），拒绝安装` | 服务端版本与实现不匹配 | 升级 Master；或 `--version` 指定一个已知完整的版本 |
| `校验和不匹配：下载 …，期望 …` | 内容被改动或传输损坏 | 重新拉取；查发布源是否被替换（这也是必须 `--pubkey` 验签的理由） |
| `没有可用的备份` | 这台机器没升级过 | 只能重新安装（用注册码 `install`，或 `reenroll` 换令牌） |
| 安装脚本报"无法获取校验和" | `/dist/SHA256SUMS` 404 | 确认已 `dist pull`、`install.mode` 不是 `off`、磁盘上是 `<版本>/SHA256SUMS` |
| 写进 `master.yaml` 的 `install.*` 一律不生效 | 这些键是**数据库设置**，不是配置文件字段；YAML 非严格解析 → 静默忽略、不报错 | 改在管理端「设置 → 安装与下载」；`install.master_url` 未设置时会回落到 `public_origin` |
| `probe-agent version` 的发布标签是本机架构（如 `linux_amd64`），不是目标架构 | 构建时没注入 `PlatformTag`（随手 `go build` 出来的就是这样） | 用 `make dist` / `scripts/build.ps1 -Dist` / `scripts/ci-cross.sh` 重建。该标签是"手上二进制是不是发布构建"的**唯一观测点**，也是 Agent 向 Master 取件时的平台标识 |
| 升级后 `version` 还是旧的 | 没重启服务 | 见 §5.3 |
| 浏览器打开后满屏 **421 · 域名不匹配** | 请求的 Host 不在当前形态允许的清单里 | 见 §2.5。常见两种：①形态是「分离」，但你在用公开域名访问 `/admin/`（或反过来）；②清单里只写了域名，而你实际用 `IP:端口` 访问。用 `curl -sI -H 'Host: <域名>' http://127.0.0.1:8080/admin/` 可直接复现，不必等浏览器 |
| 保存「分离」时被拒绝：*必须同时给出公开域名与管理域名* | 防自锁校验（拆开存会留下半配置状态） | 把两个清单一起填上再保存；已经写在 `master.yaml` 里的话，直接保存即可（校验看的是**提交之后**最终生效的清单） |
| 改了域名清单但行为没变 | 设置项为空 = 回落到 `master.yaml`；非空才顶替 | 看启动日志里的「站点形态（最终生效）」那一行，它打印的就是真正生效的形态与清单；改设置时也会另记一条日志 |
| 节点一直离线 | 令牌无效 / 时间不同步 / 网络不通 | `journalctl -u probe-agent`；确认 `master.key` 与库没被换过 |
