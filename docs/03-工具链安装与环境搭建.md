# 03 · 工具链安装与开发环境搭建

> 适用：本仓库骨架（设计文档 v3.0）· Go **≥ 1.22**（本文实测 **1.27.2**）· Windows / macOS / Linux / FreeBSD
> 目标：从一台干净机器到 `bin/probe-master` + `bin/probe-agent` 可运行，并把发布、CI、部署需要的工具一并装齐。

---

## 0. 三十秒结论

| 平台 | 三条命令 |
| --- | --- |
| **Windows** | `powershell -ExecutionPolicy Bypass -File .\scripts\setup-dev-env.ps1 -WithTools -AddToUserPath` |
| **Linux / macOS / FreeBSD** | `sh scripts/setup-dev-env.sh --tools` |
| **任意平台（构建）** | `make master agent`（无 make 见 §3.3，直接 `go build`） |

两个脚本都是**幂等**的：重跑会跳过已完成步骤。默认**用户级安装**，不写系统目录、不需要管理员（Linux 用 `sudo` 时才装到 `/usr/local`）。

## 1. 到底需要装什么

### 1.1 必需

| 组件 | 版本要求 | 用途 | 装在哪 |
| --- | --- | --- | --- |
| **Go 工具链** | ≥ 1.22（`go.mod` 声明 1.22） | 构建 Master 与 Agent | §2 |
| **Git** | 任意较新版 | 版本控制；Windows 上还提供 `sha256sum`、`sh` | `git --version` |
| **SHA-256 工具** | — | 生成 `SHA256SUMS`（12.6 / S12）；安装脚本校验产物 | Linux/Git Bash `sha256sum`、macOS `shasum -a 256`、PowerShell `Get-FileHash` |

> Go 工具链自带：编译器、标准库、`gofmt`、`go vet`、`go test`、**交叉编译能力**（无需额外工具链）。

### 1.2 推荐（发布 / CI / 安全）

| 组件 | 用途 | 对应文档 |
| --- | --- | --- |
| `govulncheck` | 依赖漏洞扫描，CI 必备 | S12 |
| `minisign`（或 `cosign`） | 给 `SHA256SUMS` 签名，`install.pubkey` 校验 | 12.6 / 12.8 / S10 |
| `golangci-lint` 或 `staticcheck` | 静态检查，比 `go vet` 更严格 | — |
| `sqlite3` CLI | 直接查看 `probe.db`、验证迁移与清理效果 | 6.x 调试 |
| Docker | 在 Linux 容器里验证产物，避免"本机能跑、线上不行" | — |
| WSL2 或一台 Linux VPS | **端到端**验证一键安装链路（systemd 只存在于 Linux） | 12.3 / 12.4 |

### 1.3 可选

| 组件 | 说明 |
| --- | --- |
| `make` | 跑仓库里的 `Makefile`；没有也能构建（§3.3） |
| Caddy / Nginx | Master 前置 TLS 反代（10. 部署与运维）；本地开发不需要 |
| Node.js ≥ 20 | **仅**在补管理后台前端（README 扩展点）时才需要；当前仓库不需要 |

### 1.4 明确**不需要**的东西（省得白装）

| 组件 | 为什么不需要 |
| --- | --- |
| **C / C++ 编译器（gcc/clang）、cgo 工具链** | 全项目 `CGO_ENABLED=0` 静态编译；SQLite 用 `modernc.org/sqlite`（纯 Go 实现），不链接 libsqlite3 |
| **各平台交叉编译工具链**（mingw、osxcross、musl-gcc…） | Go 自带跨平台编译器，关闭 cgo 后零外部依赖 |
| **SQLite 开发库**（`libsqlite3-dev`） | 同上，纯 Go 驱动 |
| **UPX** | 12.6 明确规定不使用：会触发杀软误报并增加运行内存 |
| **数据库服务器**（MySQL/PostgreSQL/Redis） | Master 内嵌 SQLite，单进程单文件 |

> ⚠️ **唯一例外**：`go test -race`（CI 约定里有）**需要 cgo，因此需要 C 编译器**。
> - Linux：`apt install -y gcc` / `dnf install -y gcc` / `apk add gcc musl-dev`
> - macOS：`xcode-select --install`
> - Windows：装 MinGW-w64（`choco install mingw` 或 `scoop install mingw`），否则 `-race` 会报 `-race requires cgo`
>
> 不装 gcc 也能正常开发和发布，只是跑不了竞态检测。

## 2. 安装 Go 工具链

### 2.0 版本选择

- 底线：**≥ 1.22**。用更老的版本会直接报 `go.mod requires go >= 1.22.0 (running go 1.18.x)`。
- 发行版仓库里的 Go 往往太旧：Ubuntu 22.04 的 `apt install golang` 是 1.18，**会失败**；Debian 12 是 1.19，也不行。要么用官方 tarball，要么用 `golang-backports`，要么加 `golang.org/dl`（见 §2.4）。
- 本文实测 **1.27.2**（截至 2026-10-11，国内镜像上最新的稳定版为 1.27.2；1.27.3 尚未入库）。
- `GOTOOLCHAIN` 机制（Go ≥ 1.21）：当 `go.mod` 声明了比当前工具链更高的版本，Go 会自动经 `GOPROXY` 下载对应工具链。本项目只声明 1.22，不需要它；脚本里统一设为 `local` 以免内网/CI 意外联网。
- 多版本共存：装到不同目录 + `current` 软链（脚本就是这么做的），或 `go install golang.org/dl/go1.23.4@latest && go1.23.4 download`。

### 2.1 Windows

#### 方式 A：官方 MSI（需要管理员，最省事）

```powershell
# 打开 https://go.dev/dl/ 下载 go1.27.2.windows-amd64.msi 双击安装
# 或用包管理器：
winget install --id GoLang.Go -e
choco install golang -y
scoop install go
```

装到 `C:\Program Files\Go`，自动配置机器级 PATH。缺点：需要管理员；**国内 go.dev 常常打不开**。

#### 方式 B：zip 免管理员（推荐：国内网络 / 无管理员权限 / 不想污染系统）

```powershell
# 1) 下载（官方站不通就用国内镜像，见方式 C）
$url = "https://go.dev/dl/go1.27.2.windows-amd64.zip"
# 2) 解压到用户目录（不要解压到 C:\Program Files）
$dst = "$env:USERPROFILE\.workbuddy\binaries\go\go1.27.2"
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.workbuddy\binaries\go\downloads" | Out-Null
curl.exe -fL -o "$env:USERPROFILE\.workbuddy\binaries\go\downloads\go1.27.2.windows-amd64.zip" $url
Expand-Archive -Path "$env:USERPROFILE\.workbuddy\binaries\go\downloads\go1.27.2.windows-amd64.zip" -DestinationPath "$env:USERPROFILE\.workbuddy\binaries\go" -Force
# 3) 写入用户级 PATH（新终端生效，不影响其他用户、不需要管理员）
$bin = "$env:USERPROFILE\.workbuddy\binaries\go\go1.27.2\go\bin"
$old = [Environment]::GetEnvironmentVariable('Path','User')
if ($old -notlike "*$bin*") { [Environment]::SetEnvironmentVariable('Path', ($old.TrimEnd(';') + ';' + $bin), 'User') }
# 4) 当前会话立即生效并验证
$env:Path = "$bin;$env:Path"; go version
```

> 以上全过程已被 `scripts\setup-dev-env.ps1` 自动化，直接用脚本即可。
> **校验和**：`Get-FileHash .\go1.27.2.windows-amd64.zip -Algorithm SHA256` 与官方 `https://go.dev/dl/go1.27.2.windows-amd64.zip.sha256` 比对。

#### 方式 C：国内镜像（go.dev 不可达时）

```powershell
# 可用镜像（2026-10-11 实测：以下三个均可访问，go.dev / golang.google.cn / dl.google.com 均不可达）
#   阿里云   https://mirrors.aliyun.com/golang/
#   中科大   https://mirrors.ustc.edu.cn/golang/
#   清华     https://mirrors.tuna.tsinghua.edu.cn/golang/
$base = "https://mirrors.aliyun.com/golang"
$file = "go1.27.2.windows-amd64.zip"
curl.exe -fL -o "$env:TEMP\$file" "$base/$file"
```

**镜像的坑**：网页版文件列表很长，服务端会把 HTML 截断，看起来"最新只有 1.23"，其实新版本文件确实在。
**正确做法是直接按 `go<版本>.windows-amd64.zip` 拼 URL 探测**（`curl.exe -fsIL` 看状态码）。本机实测 `go1.27.3` → 404、`go1.27.2` → 200，即最新为 1.27.2。

#### 方式 D：包管理器

```powershell
winget install --id GoLang.Go -e     # Windows 官方 MSI，需管理员
choco install golang -y              # 需管理员
scoop install go                     # 免管理员，装到 ~\scoop\
```

### 2.2 macOS

```bash
# 方式 A：Homebrew（最省事；注意 go 会被 brew 一起升级）
brew install go

# 方式 B：官方 pkg（图形安装，装到 /usr/local/go）
#   https://go.dev/dl/go1.27.2.darwin-arm64.pkg   （Apple Silicon）
#   https://go.dev/dl/go1.27.2.darwin-amd64.pkg   （Intel）

# 方式 C：手动 tarball 到用户目录（推荐：版本可控、随时回滚、不需要 sudo）
VER=1.27.2
ARCH=$(uname -m); [ "$ARCH" = "x86_64" ] && GOARCH=amd64 || GOARCH=arm64
PREFIX="$HOME/.local/share/probe-go"; mkdir -p "$PREFIX/downloads"
curl -fL -o "$PREFIX/downloads/go$VER.darwin-$GOARCH.tar.gz" \
  "https://go.dev/dl/go$VER.darwin-$GOARCH.tar.gz"      # 不通则换 mirrors.aliyun.com/golang
shasum -a 256 "$PREFIX/downloads/go$VER.darwin-$GOARCH.tar.gz"   # 与官方 .sha256 比对
mkdir -p "$PREFIX/go$VER" && tar -C "$PREFIX/go$VER" -xzf "$PREFIX/downloads/go$VER.darwin-$GOARCH.tar.gz"
ln -sfn "$PREFIX/go$VER/go" "$PREFIX/current"
echo 'export PATH="$HOME/.local/share/probe-go/current/bin:$PATH"' >> ~/.zshrc
exec zsh -l; go version
```

注意事项：
- Apple Silicon 用 `darwin-arm64`，Intel 用 `darwin-amd64`，**Mac 只有 tar.gz，没有 zip**（实测 darwin 的 zip 产物 404）。
- 系统自带 `curl` 与 `shasum`，无需额外安装。
- 别用系统 Python 那种思路去动 `/usr/local/go`——Homebrew 与官方 pkg 会互相覆盖。

### 2.3 Linux / FreeBSD

```bash
# 方式 A：官方 tarball（推荐，任何发行版通用）
VER=1.27.2
ARCH=$(uname -m)
case "$ARCH" in
  x86_64|amd64)  TAG=amd64 ;;
  aarch64|arm64) TAG=arm64 ;;
  armv7l)        TAG=armv6l ;;     # Go 不发布 32 位 ARM 的 armv7 包，只有 armv6l
  armv6l)        TAG=armv6l ;;
  i386|i686)     TAG=386 ;;
  riscv64)       TAG=riscv64 ;;
  loongarch64)   TAG=loong64 ;;
esac
PREFIX="$HOME/.local/share/probe-go"        # 想装系统级就 PREFIX=/usr/local（需 sudo）
mkdir -p "$PREFIX/downloads"
curl -fL -o "$PREFIX/downloads/go$VER.linux-$TAG.tar.gz" \
  "https://go.dev/dl/go$VER.linux-$TAG.tar.gz"   # 不通则换 mirrors.aliyun.com/golang
sha256sum "$PREFIX/downloads/go$VER.linux-$TAG.tar.gz"
mkdir -p "$PREFIX/go$VER" && tar -C "$PREFIX/go$VER" -xzf "$PREFIX/downloads/go$VER.linux-$TAG.tar.gz"
ln -sfn "$PREFIX/go$VER/go" "$PREFIX/current"
echo 'export PATH="$HOME/.local/share/probe-go/current/bin:$PATH"' >> ~/.bashrc
exec bash -l; go version

# 方式 B：发行版包（先确认版本！低于 1.22 就别用）
sudo apt install -y golang-go     # Debian/Ubuntu：22.04 是 1.18 ✗，24.04 是 1.22 ✓
sudo dnf install -y golang        # Fedora 39+ 通常满足
sudo apk add go                   # Alpine
sudo pacman -S go                 # Arch
sudo pkg install -y go            # FreeBSD（ports，通常较新）

# 方式 C：snap（版本新，但沙箱对 GOPATH 有影响，不推荐用于 CI）
sudo snap install go --classic
```

**架构产物对照（2026-10-11 实测阿里云镜像）**：

| 目标 | tar 后缀 | 存在 |
| --- | --- | --- |
| Linux amd64 / arm64 / 386 / riscv64 / loong64 | `linux-amd64` / `linux-arm64` / `linux-386` / `linux-riscv64` / `linux-loong64` | ✅ |
| Linux 32 位 ARM | `linux-armv6l`（**无 `armv7l`**） | ✅ |
| Linux armv7l | `linux-armv7l` | ❌ 404 |
| macOS | `darwin-amd64` / `darwin-arm64`（仅 tar.gz） | ✅ |
| FreeBSD | `freebsd-amd64` / `freebsd-arm64` | ✅ |
| Windows | `windows-amd64` / `windows-arm64`（仅 zip，无 tar.gz） | ✅ |

## 3. 环境变量与国内加速

### 3.1 一次性配置

```bash
# 模块代理：国内首选（本项目所有依赖都能取到）
go env -w GOPROXY=https://goproxy.cn,direct

# 备选（任一）
#   https://goproxy.io,direct
#   https://mirrors.aliyun.com/goproxy/,direct
#   https://mirrors.tencent.com/go/,direct

# 关闭工具链自动下载（go.mod 只声明 1.22，不需要；避免内网/CI 意外联网）
go env -w GOTOOLCHAIN=local

# 可选：把构建缓存放到大盘（默认在 C:\Users\<你>\AppData\Local\go-build）
# go env -w GOCACHE=D:\gocache
```

**关于校验和数据库（GOSUMDB）**：设置 `GOPROXY` 后，Go 会**经由代理的 `/sumdb/` 端点**访问 `sum.golang.org`，所以国内不需要额外把 `GOSUMDB` 指向 `sum.golang.google.cn`（该域名在本机实测不可达）。保持默认即可；只有在代理明确不支持 sumdb 时才设 `GONOSUMCHECK`/`GOSUMDB=off`（会降低供应链安全性，S12）。

**`go env -w` 写在哪**：Windows `%APPDATA%\go\env`；Linux/macOS `$XDG_CONFIG_HOME/go/env`（通常是 `~/.config/go/env`）。用 `go env -u KEY` 撤销。

### 3.2 vendor/：本机可选，**不随仓库提交**

依赖由 `go.mod` + `go.sum` 锁定，仓库里**没有** `vendor/`。在项目根目录执行：

```bash
go mod tidy        # 计算完整依赖图、补全 go.sum，并把模块拉进 GOMODCACHE
```

- 直接依赖只有 5 个（`x/crypto`、`x/net`、`x/time`、`yaml.v3`、`modernc.org/sqlite`），
  连间接依赖合计 **18 个模块**，`go mod download` 几 MB 就能取全。
- **为什么不用 vendor/**：`go mod vendor` 会把 `modernc.org/libc` / `modernc.org/sqlite`
  各架构的生成代码一起落盘，实测 **197 MB**（其中 `modernc.org` 占 190 MB）。压缩后仍有
  几十 MB，每次克隆都要付这个体积；而收益仅仅是"离线构建"，可依赖只有 18 个模块，
  留在 `GOMODCACHE` 里就够。所以仓库只提交 `go.mod` + `go.sum`，构建与 CI 一律
  `go mod download`（见 `.gitignore` 末尾与 `.github/workflows/ci.yml` 头注释）。
- ⚠️ **本机可以自行 `go mod vendor`** 换取离线构建（那份目录已被 `.gitignore` 排除，不会
  误入库）。但要记住它的副作用：**只要 `vendor/` 在磁盘上，Go 就自动切到 `-mod=vendor`**；
  此后一旦改了 `go.mod` 而没重新 vendor，会报 `go: inconsistent vendoring`。
  这是本机残留、不是配置错误——重新 `go mod vendor` 或直接删掉该目录即可。
- ⚠️ **不要**在没有 `vendor/` 目录时设 `GOFLAGS=-mod=vendor`，同样会得到
  `go: inconsistent vendoring`。默认的 `-mod=readonly` 才是本仓库期望的行为：
  依赖缺失时立刻报错，而不是偷偷改写 `go.mod`。
- 真正完全离线的机器（没有 GOPROXY）：见 §6，把 `$(go env GOMODCACHE)` 打包搬过去。
- 只有 Master 用到 SQLite；Agent 不依赖它，所以 `make dist`（仅编 Agent）可以覆盖全部平台。

### 3.3 磁盘与缓存

| 路径 | 内容 | 大致体积 |
| --- | --- | --- |
| `GOROOT` | 工具链本体 | ~450 MB（1.27） |
| `GOMODCACHE` | 模块缓存（本仓库的依赖来源） | 首次 tidy 后 ~50 MB |
| `GOCACHE` | 构建缓存 | 数百 MB，可随时 `go clean -cache` |
| `vendor/`（本机可选，**不入库**） | 依赖源码副本 | 约 197 MB，仅在你执行过 `go mod vendor` 后存在 |

## 4. 构建本项目

### 4.1 首次构建

```bash
go mod tidy
go vet ./...
go build ./...                       # 只编译不产出，最快发现编译错误

# 产出二进制（与 Makefile 一致）
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=1.0.0" -o bin/probe-master ./cmd/probe-master
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=1.0.0" -o bin/probe-agent  ./cmd/probe-agent
```

### 4.2 用 Makefile

```bash
make tidy          # go mod tidy
make fmt           # gofmt -w -s .
make vet           # go vet ./...
make test          # go test ./...
make master agent  # 编两个二进制到 bin/
make dist          # 交叉编译全部平台到 dist/1.0.0/ 并生成 SHA256SUMS
make clean
```

**Windows 上没有 make**，三种替代：

```powershell
# 方案 1（推荐）：用仓库脚本，不依赖 make
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1

# 方案 2：装 make
scoop install make            # 免管理员
choco install make -y         # 需管理员
# 装完在 Git Bash 里 make master agent

# 方案 3：不用 make，直接敲 go build（见 4.1）
```

> `Makefile` 里的规则使用了 POSIX shell 循环、`mkdir -p`、`sha256sum`，**必须在 Git Bash / WSL / 类 Unix 环境**执行；PowerShell 直接跑 `make` 会失败。

### 4.3 交叉编译（发布 Agent）

```bash
GOOS=linux  GOARCH=arm64 go build -o probe-agent_linux_arm64  ./cmd/probe-agent
GOOS=darwin GOARCH=arm64 go build -o probe-agent_darwin_arm64 ./cmd/probe-agent
GOOS=windows GOARCH=amd64 go build -o probe-agent_windows_amd64.exe ./cmd/probe-agent
```

- 32 位 ARM 要额外给 `GOARM`：`GOOS=linux GOARCH=arm GOARM=7`。
- **`armv7` 不是合法的 `GOARCH`**——`GOARCH` 只有 `arm`，版本靠 `GOARM` 表达。`go tool dist list` 可确认。
- Master 只在宿主平台构建（它要链接 SQLite 驱动，跨平台价值也低）。

### 4.4 本机冒烟运行（开发环回）

```bash
cp configs/master.yaml.example master.yaml
#   data_dir 改成可写路径，例如 ./data；tls.mode 保持 none（本地开发用 http）
./bin/probe-master init-admin --config ./master.yaml --username admin
./bin/probe-master --config ./master.yaml          # 监听 127.0.0.1:8080 / :8081

# Agent 本机自测：--no-service 跳过服务注册，--insecure-http 仅回环放行（S7）
./bin/probe-agent install --master http://127.0.0.1:8080 --code <后台生成的注册码> \
    --no-service --dir ./dev-agent --insecure-http
./bin/probe-agent run --config ./dev-agent/agent.yaml
```

> `--insecure-http` 是唯一的 http 放行开关，且只应对回环地址使用；生产必须 https（S7）。

### 5.2 govulncheck（CI 必需）

### 5.4 minisign（发布产物签名，12.6 / 12.8 / S10）

### 5.6 Caddy / Nginx（部署时前置 TLS）

> **也可以不用它**。6.3 之后 Master 自己能终结 TLS：`tls.mode` 支持
> `files`（自带证书，热加载）/ `selfsigned`（自签，SAN 可含 IP）/ `acme`（内置零依赖
> ACME v2 客户端，自动申请并续期**域名证书**与 **RFC 8738 IP 证书**）。
> 只有当你已经有一套反代体系、或想共用一张证书时才需要下面这套；
> 走本机 TLS 时记得**不要**再配 `trusted_proxies`，并把 `tls.mode` 设为对应值。
> 完整样例见 `configs/master.yaml.example` 与 README「TLS 与证书」。

```bash
# Caddy：自动 HTTPS，最省心（推荐，对应 10. 部署与运维）
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```
```
# /etc/caddy/Caddyfile —— 公开站与管理端分成两个源（13.4.5 推荐）
status.example.com {
    reverse_proxy 127.0.0.1:8080
}
admin.example.com {
    reverse_proxy 127.0.0.1:8081
}
```
Nginx 同理；两者都要把 Master 的 `trusted_proxies` 配成 `127.0.0.1`，否则 Master 拿不到真实来源 IP（S5），
也认不了 `X-Forwarded-Proto: https`（会话 Cookie 会降级、HSTS 不会下发）。

分成两个源之后，**把同样的两个域名写进 Master**（`public_origin` / `admin_origin`），
否则用公开域名访问 `/admin/` 不会被拦（Host 门禁没生效）：

```yaml
public_origin: "https://status.example.com"
admin_origin:  "https://admin.example.com"
```

顺便：Caddy 若要用 HTTP-01 帮你签证书，它自己会占用 80 端口；
这时 Master 侧应该走 `tls.mode: none`（证书由 Caddy 管），不要两边都去抢 80 端口。

## 6. 离线 / 内网环境

1. **联网机器**上执行一次 `go mod tidy`（等价于取全依赖），把模块缓存准备就绪。
2. 打包 `$(go env GOMODCACHE)`（首次 tidy 后约 50 MB），解到**离线机**的同名路径下。
3. 也可以走 `vendor/` 这条路：在联网机上 `go mod vendor`，把整个 `vendor/` 目录一起搬过去；
   Go 会因为存在 `vendor/` 自动使用 `-mod=vendor`，全程不联网。注意 `vendor/` **不入库**
   （见 §3.2），所以这是"自己搬"，不是"clone 下来就有"。
4. 私有代理：设 `GOPROXY=http://nexus.internal/repository/go/`，并视情况配 `GONOSUMDB`/`GOPRIVATE`。本项目模块路径是占位符 `github.com/yourorg/probe`，**不需要**配 GOPRIVATE。
5. 工具链也在内网用：把 Go 的 zip/tar 放到内网文件服务器，脚本支持 `--dir` + 预置缓存包（`<InstallRoot>/downloads/` 下放好压缩包，脚本会跳过下载）。

## 7. 常见报错与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `go: command not found` | PATH 未生效 | 新开终端；或 `export PATH=/usr/local/go/bin:$PATH`；Windows 检查用户级 PATH |
| `go.mod requires go >= 1.22.0 (running go 1.18.1)` | 发行版包太旧 | 升级 Go（§2） |
| `missing go.sum entry for module ...` | 未 tidy | `go mod tidy` |
| `module lookup disabled by GOPROXY=off` | 代理被显式关闭 | `go env -w GOPROXY=https://goproxy.cn,direct` |
| `dial tcp ...: i/o timeout`（拉 proxy.golang.org） | 官方代理被墙 | 换 `goproxy.cn` |
| `verifying module: ... 404` / sumdb 超时 | 校验和库不可达 | 确认代理支持 `/sumdb/`；仍失败再考虑 `GOFLAGS=-mod=mod GONOSUMCHECK=1`（安全性下降，S12 需评估） |
| `go: inconsistent vendoring` | **本机**有 `vendor/` 但和 `go.mod` 不一致（本仓库不提交 `vendor/`，所以这只可能是自己 vendor 过又改了 `go.mod`） | `go mod vendor` 重新生成，或直接删掉 `vendor/` 目录（见 §3.2） |
| `-race requires cgo` / `gcc: not found` | 缺 C 编译器 | 装 gcc（§5.10）或先不跑 `-race` |
| `unsupported GOOS/GOARCH pair linux/armv7` | `armv7` 不是 GOARCH | 用 `GOARCH=arm GOARM=7` |
| `pattern builtin: no matching files found`（`go:embed`） | 被 embed 的目录/文件不存在或不在包目录下 | 检查 `internal/theme/builtin/`、`internal/api/scripts/`、`internal/db/migrations/` 是否齐全 |
| 构建很慢、杀软告警 | 实时扫描 Go 构建缓存；Agent 含 TCP/ICMP 探测代码易被启发式规则命中 | 把项目目录、`GOCACHE`、`GOMODCACHE` 加入 Defender 排除项；不要用 UPX |
| `make: command not found` | 未装 make | §5.1，或直接 `go build`/用 `scripts\build.ps1` |
| PowerShell 里 `make` 报语法错误 | Makefile 用的是 sh 语法 | 在 Git Bash / WSL 里跑 |
| `tar: Error opening archive` | 下载被截断 | 删掉缓存压缩包重下；核对 SHA-256 |
| 路径含中文/空格导致奇怪失败 | 少数组件对非 ASCII 路径处理不佳 | 项目与 `GOCACHE` 尽量放纯 ASCII 路径 |
| Windows 上 `go build` 报 `Access is denied` | 二进制正在运行 | 先停掉进程/服务再覆盖 |
